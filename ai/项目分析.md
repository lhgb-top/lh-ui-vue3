# lh-ui-plus 项目分析与优化方案

## 一、项目总结

**lh-ui-plus** 是一个基于 **Vue 3 + TypeScript** 的 UI 组件库，采用**国风主题**设计（青花瓷蓝、松花绿、藤黄、朱砂等传统色系）。

### 核心特性

- Vue 3 Composition API
- CSS 变量主题系统，支持暗色主题
- 国际化（zh-CN / en-US）
- ConfigProvider 全局配置（尺寸、主题、语言）
- 支持 ESM / CJS / UMD 多种构建格式
- Tree-shaking（ESM 按需引入）

---

## 二、项目运行

```bash
pnpm install                    # 安装依赖
pnpm dev                        # Vite 开发预览
pnpm build                      # 全量构建（ESM + CJS + 样式 + DTS）
pnpm build:umd                  # 单独构建 UMD
pnpm docs:dev                   # 文档站开发
```

### 架构分层

**三层架构设计：**

1. **Core 层** (`packages/core/`) — 纯函数逻辑，框架无关
2. **Components 层** (`packages/components/`) — Vue SFC 组件，负责渲染
3. **Theme 层** (`packages/theme/`) — CSS 变量 + SCSS，国风主题

#### 1.5 测试策略

**Core 层（100% 覆盖目标）**

Core 层是纯函数，易于测试。每个 `logic.ts` 对应一个 `.spec.ts`：

- **`button/logic.ts`**: 测试 `isClickable`, `getSize`, `getClassNames`, `getStyle`
- **`input/logic.ts`**: 测试 `getWordCount`, `shouldShowWordLimit`, `clampValue`, `getInputStyle`
- **`dialog/logic.ts`**: 测试 `canClose`, `getDialogStyle`, `getDialogPopperClass`
- **`config/logic.ts`**: 测试 `mergeConfig`, `getEffectiveSize`, `getEffectiveZIndex`

示例 — 按钮 Core 测试：

```ts
import { describe, it, expect } from 'vitest'
import { isClickable, getSize, getClassNames } from '~/core/button'

describe('button/core/logic', () => {
  it('isClickable returns false when loading', () => {
    expect(isClickable({ loading: true, disabled: false })).toBe(false)
  })

  it('isClickable returns false when disabled', () => {
    expect(isClickable({ loading: false, disabled: true })).toBe(false)
  })

  it('isClickable returns true when clickable', () => {
    expect(isClickable({ loading: false, disabled: false })).toBe(true)
  })

  it('getSize priority: local > global > default', () => {
    expect(getSize('small', 'large')).toBe('small')
    expect(getSize(undefined, 'large')).toBe('large')
    expect(getSize(undefined, undefined)).toBe('medium')
  })

  it('getClassNames builds correct class array', () => {
    const state = {
      type: 'primary',
      size: 'medium',
      loading: false,
      disabled: false,
      plain: true,
      block: false,
      round: false,
      circle: false,
    }
    const classes = getClassNames(state)
    expect(classes).toContain('lh-button')
    expect(classes).toContain('lh-button--primary')
    expect(classes).toContain('lh-button--plain')
  })
})
```

### 2. 构建工具升级

#### 2.1 问题诊断

- **TypeScript 插件链重复**: JavaScript 构建同时依赖 Vue SFC 转换和 TypeScript 转换，容易与 Vue 虚拟模块冲突
- **`rollup-plugin-vue@6` 兼容性不足**: 当前 Vue 编译器需要文件系统能力解析 SFC 类型，旧插件无法完整传递该能力
- **缺少独立 dts 构建**: `rollup-plugin-dts` 已安装但未使用时，构建后缺少稳定的入口声明文件
- **发布入口需要与实际产物同步**: `package.json` 曾指向不存在的 `.mjs` 和 UMD 文件名

#### 2.2 实施方案

**Phase 1: 统一 TypeScript 插件**

- 移除 `rollup-plugin-typescript2` 和未使用的 `@rollup/plugin-typescript`
- 使用 `rollup-plugin-esbuild` 负责 JavaScript/TypeScript 转译
- 使用 `@vitejs/plugin-vue` 处理 Vue SFC
- 添加 `@rollup/plugin-alias`，统一解析项目内部路径别名

**Phase 2: 添加 dts 构建**

- 新增 `rollup.dts.config.js`，为根入口、常量、语言包和每个组件生成 `.d.ts` 声明文件
- 确保 `types` 字段在 `package.json` 正确指向生成的声明文件

**Phase 3: 修复 `prepublishOnly`**

- 将 `npm run build` 改为 `pnpm run build`

#### 2.3 Vue SFC 构建方案

当前使用 `@vitejs/plugin-vue` + `rollup-plugin-esbuild`：前者负责 SFC 模板和样式拆分，后者负责 Vue 虚拟 TypeScript 脚本及普通 TypeScript 入口转译。DTS 使用独立 Rollup 配置，避免 JavaScript 构建插件和声明生成互相干扰。
