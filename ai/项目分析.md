## 一、项目总结

**lh-ui-plus** 是一个基于 **Vue 3 + TypeScript** 的 UI 组件库，采用**国风主题**设计（青花瓷蓝、松花绿、藤黄、朱砂等传统色系）。

### 核心特性

- Vue 3 Composition API，组件逻辑与纯函数分层
- CSS 变量主题系统，支持暗色主题
- 国际化（zh-CN / en-US）
- ConfigProvider 全局配置（尺寸、主题、语言、花纹白名单）
- 支持 ESM / CJS / UMD 多种构建格式
- Tree-shaking（ESM 按需引入）

### 架构分层

**三层架构设计：**

1. **Core 层** (`packages/core/`) — 纯函数逻辑，框架无关（**禁止引入 Vue**）
2. **Components 层** (`packages/components/`) — Vue SFC 组件，负责渲染与样式
3. **Theme 层** (`packages/theme/`) — CSS 变量 + SCSS，国风主题

数据流：`src/index.ts`（公共入口）→ `packages/components/index.ts`（`lhComponents` 注册清单）→ 各组件 `index.ts` → `src/index.vue` + `useLhXxx()` composable → `@lh-ui/core/<name>/logic.ts`。

## 六、优化计划（按优先级重排）

### P0 — 阻塞项：修复构建与既有缺陷

> ✅ **本节全部完成（2026-09-15 第二轮）**，修复明细见 §5.1''。以下保留原始诊断作为问题记录。

#### P0-1 修复构建链路（双根因）

**根因 A — SFC 内联样式产出 `.cs` 虚拟模块无人处理**

- `rollup.config.js` 的 `createBasePlugins()` 中 `scss({ include: ['packages/**/*.scss'] })`；
  `@vitejs/plugin-vue` 会把 SFC 的 `<style>` 块拆成虚拟模块：
  - 带 `lang="scss"` → 模块 id 以 `…&lang.scss` 结尾，**能**被上述 include 命中（`config-provider` 即属此类）
  - 无 `lang` 的纯 CSS → 模块 id 以 `…&lang.css` 结尾，**不能**命中，且无其他插件处理 → Rollup 按 JS 解析 CSS → `Expression expected`
- 触发文件：`packages/components/date-picker/src/index.vue`（`<style scoped>`）、`packages/components/time-picker/src/index.vue`（`<style scoped>`）
- **推荐修复**：按项目规范把这两处内联样式迁入各自的 `style/index.scss`。这既消除构建错误，也恢复「组件样式统一由 `style/index.scss` 承载、通过 `src/index.ts` 聚合引入」的既有契约。
- **加固措施**：为纯 CSS 虚拟模块补一个 `css` 处理插件（或放宽 scss `include` 同时覆盖 `lang.css`），避免后续组件再次踩坑。

**根因 B — dts 构建无法处理样式导入**

- `rollup.dts.config.js` 的 `createDeclarationEntries()` 只把 `.vue` 与 `vue` 标为 `external`，也无 SCSS 处理；
  而 `src/index.ts` 现在会 `import '../packages/components/<name>/style/index.scss'`，于是 `dts()` 在解析
  `packages/components/button/style/index.scss` 时报 `Expected ';', '}' or <eof>`。
- **推荐修复**：在 dts 条目的 `external` 中追加 `/\.s?css$/`（声明文件无需包含样式），并在 `resolveId` 钩子中把样式请求直接外置。
- **顺带修复**：`rollup.dts.config.js` 的别名 `{ find: 'constants' }` 与实际导入的 `lh-constants` 不匹配（拼写遗漏 `lh-`），属潜在解析缺陷。

**验收**：`pnpm build && pnpm build:dts && pnpm build:umd` 全部通过，且 `dist/lh-ui-plus.js`、`es/<name>/style/index.css`、各 `.d.ts` 均生成。

#### P0-2 修复 Badge 组件实现缺陷

`LhBadge` 已注册并已有测试，但当前实现存在**真实缺陷**（6 个测试失败是其表征，不是测试写错）：

| 问题 | 具体表现 | 影响 |
| ---- | -------- | ---- |
| 类名与样式脱节 | SCSS 全部作用于 `.lh-badge__content` 与 `.lh-badge--{type,size,dot} .lh-badge__content`，而组件把基类 `lh-badge`（缺 `__content`）放到 `<sup>` | 徽标胶囊的背景色、定位、圆角、尺寸**完全不生效**，视觉上未实现 |
| 修饰类层级错误 | `getBadgeClassNames()` 产出的 `lh-badge--primary` 等落在 `<sup>`，测试断言的是根 `<div>` 的 `classes()` | 4 个用例失败（type / size / dot） |
| `<teleport to="body">` | 内容被移出 wrapper 根节点 | `wrapper.text()` 为空、`wrapper.find('sup')` 为 false，3 个用例失败；且组件卸载时缺少 body 清理 |

**推荐修复**：

1. `packages/core/badge/logic.ts` 的基类改为 `lh-badge__content`，并保持修饰类与 SCSS 选择器一一对应；
2. `src/index.vue` 让 `<sup>` 承载 `lh-badge__content` 基类，根 `<div>` 只负责定位容器；
3. 移除默认 `teleport`（改为显式可选），或保留时在 `onBeforeUnmount` 中清理并让测试改用 `attachTo`/`document.body` 查询；
4. 测试改为对内部元素断言，并补一条「type/size 修饰类只出现在内容元素」的回归用例。

#### P0-3 修正注册清单测试

- `tests/unit/components-registry.spec.ts` 的期望清单止于 `LhTag`，漏了数组末位的 `LhBadge`。
- 该测试断言的是**有序全等**，因此每次新增组件都必须同步更新，建议在交付清单中固化为必做步骤（见 §7）。

#### P0-4 修复 i18n 运行时崩溃（已实测复现）

- `packages/components/cascader/src/index.vue:187` 写的是 `const t = lhlocale.t`，解构后 `this` 丢失。
- 实测：`TypeError: Cannot read properties of undefined (reading 'messages')`；直接调用 `lhlocale.t('cascader.noMatch')` 正常返回「无匹配数据」。
- 因此 Cascader 在**搜索无结果**分支渲染时必崩。现有 10 个 Cascader 测试全部通过，只是因为未覆盖该分支。
- **推荐修复**：改为 `const t = (path: string, fallback?: string) => lhlocale.t(path, fallback)`，或在 `LhLocale` 中将 `t` 定义为箭头函数属性 / 使用 `bind`。
- **同时**：补一条覆盖 `noMatch` 空结果的回归测试。

## 七、组件交付规范（对齐 `docs/project/development-guide.md`）

新增组件必须完整走完以下 8 步，任何一步缺失都会导致门禁或文档不一致——本轮 Tag/Badge/Cascader/TimePicker 的问题正是漏了第 4、7、8 步。

1. **Core 纯逻辑**：`packages/core/<name>/`（`logic.ts` / `types.ts` / `index.ts`），不得引入 Vue；同步新增 `tests/unit/core/<name>.spec.ts`。
2. **组件目录**：`packages/components/<name>/`，含 `index.ts`（默认导出 + `.install()` + 类型 re-export）、`src/index.vue`、`src/index.ts`（`useLhXxx` composable）、`src/types.ts`（props + `LH_XXX_TYPE_CONST` / `LH_XXX_SIZE_CONST`）、`types.ts`（re-export）、`style/index.scss`。
3. **双入口注册**：`packages/components/index.ts` 的 `lhComponents` + 命名导出；`src/index.ts` 的命名导出、类型导出、`style/index.scss` 引入。
4. **更新注册清单测试**：`tests/unit/components-registry.spec.ts` 的期望名称数组（有序全等，必须同步）。
5. **组件测试**：`tests/components/<name>.spec.ts`，至少覆盖渲染、props 类名、事件与一个边界行为。
6. **文档三处齐备**：`docs/components/<name>.md` + `docs/.vitepress/config.ts` 侧边栏条目 + `docs/.vitepress/theme/index.ts` 全局注册与样式引入。
7. **Changeset**：`.changeset/<name>.md`，格式见现有条目。
8. **门禁全绿**：`pnpm lint && pnpm typecheck && pnpm test:unit && pnpm test:components && pnpm docs:build && pnpm build`。

样式约定：组件样式一律写在 `style/index.scss`，以 `@use '../../../theme/src/common/index.scss' as *;` 开头；**不要在 SFC 内写 `<style>` 块**（这正是 P0-1 的成因）。
