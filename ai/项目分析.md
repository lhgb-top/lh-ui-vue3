## 一、项目总结

**lh-ui-plus** 是一个基于 **Vue 3 + TypeScript** 的 UI 组件库，采用**国风主题**设计（青花瓷蓝、松花绿、藤黄、朱砂等传统色系）。

### 核心特性

- Vue 3 Composition API，组件逻辑与纯函数分层
- CSS 变量主题系统，支持暗色主题
- 国际化（zh-CN / en-US）
- ConfigProvider 全局配置（尺寸、主题、语言、花纹白名单）
- 支持 ESM / CJS / UMD 多种构建格式
- Tree-shaking（ESM 按需引入）

### 架构分层

**三层架构设计：**

1. **Core 层** (`packages/core/`) — 纯函数逻辑，框架无关（**禁止引入 Vue**）
2. **Components 层** (`packages/components/`) — Vue SFC 组件，负责渲染与样式
3. **Theme 层** (`packages/theme/`) — CSS 变量 + SCSS，国风主题

数据流：`src/index.ts`（公共入口）→ `packages/components/index.ts`（`lhComponents` 注册清单）→ 各组件 `index.ts` → `src/index.vue` + `useLhXxx()` composable → `@lh-ui/core/<name>/logic.ts`。

## 二、项目运行

```bash
pnpm install                    # 安装依赖（.npmrc 已设 shamefully-hoist）
pnpm dev                        # Vite 开发预览（dev/ 目录）
pnpm typecheck                  # tsc --noEmit
pnpm lint                       # ESLint flat config
pnpm test:unit                  # tests/unit
pnpm test:components            # tests/components
pnpm test:coverage              # 覆盖率报告
pnpm docs:dev                   # VitePress 文档站
pnpm docs:build                 # 文档构建
pnpm build                      # 全量构建（ESM + CJS + 主题样式 + 组件样式）
pnpm build:dts                  # 声明文件
pnpm build:esm | build:cjs | build:umd
pnpm changeset                  # 记录变更
```

### P0 — 阻塞项：修复构建与既有缺陷

> ✅ **本节全部完成（2026-09-15 第二轮）**，修复明细见 §5.1''。以下保留原始诊断作为问题记录。

#### P0-1 修复构建链路（双根因）

**根因 A — SFC 内联样式产出 `.cs` 虚拟模块无人处理**

- `rollup.config.js` 的 `createBasePlugins()` 中 `scss({ include: ['packages/**/*.scss'] })`；
  `@vitejs/plugin-vue` 会把 SFC 的 `<style>` 块拆成虚拟模块：
  - 带 `lang="scss"` → 模块 id 以 `…&lang.scss` 结尾，**能**被上述 include 命中（`config-provider` 即属此类）
  - 无 `lang` 的纯 CSS → 模块 id 以 `…&lang.css` 结尾，**不能**命中，且无其他插件处理 → Rollup 按 JS 解析 CSS → `Expression expected`
- 触发文件：`packages/components/date-picker/src/index.vue`（`<style scoped>`）、`packages/components/time-picker/src/index.vue`（`<style scoped>`）
- **推荐修复**：按项目规范把这两处内联样式迁入各自的 `style/index.scss`。这既消除构建错误，也恢复「组件样式统一由 `style/index.scss` 承载、通过 `src/index.ts` 聚合引入」的既有契约。
- **加固措施**：为纯 CSS 虚拟模块补一个 `css` 处理插件（或放宽 scss `include` 同时覆盖 `lang.css`），避免后续组件再次踩坑。

**根因 B — dts 构建无法处理样式导入**

- `rollup.dts.config.js` 的 `createDeclarationEntries()` 只把 `.vue` 与 `vue` 标为 `external`，也无 SCSS 处理；
  而 `src/index.ts` 现在会 `import '../packages/components/<name>/style/index.scss'`，于是 `dts()` 在解析
